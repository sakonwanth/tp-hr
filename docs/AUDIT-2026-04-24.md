# TP-HR Full Audit (2026-04-24)

เอกสารนี้สรุปผลการตรวจสอบระบบ `tp-hr` แบบ “full audit” รอบแรก โดยโฟกัส **ความถูกต้องของระบบ**, **ความปลอดภัย**, และ **แนวทางยกระดับ UX/UI ให้ mobile-first** ให้ใกล้เคียงระบบ Checkin

## สถานะ

- วันที่เริ่ม audit: 2026-04-24
- ขอบเขต: `tp-hr` ทั้งระบบ (web + api + external api v1) และจุดเชื่อมกับ `tp-common`/`tp-crm` ที่มีผลต่อ HR

## Quick Wins ที่แก้แล้วในโค้ด (ยังไม่ deploy)

### 1) CSRF enforcement (Critical)

- ปัญหา: บางหน้าสำคัญเรียก `verifyCsrfToken()` แต่ **ไม่ได้ตรวจผลลัพธ์** ทำให้คำสั่ง POST อาจถูกประมวลผลแม้ token ผิด/หมดอายุ
- แก้แล้ว:
  - `hr/settings.php`
  - `hr/dayoff_approvals.php`

### 2) CSRF token ผ่าน header (Correctness + UX)

- ปัญหา: frontend helper (`templates/footer.php`) ส่ง token ผ่าน `X-CSRF-Token` แต่ backend ไม่อ่าน header → บางฟังก์ชันที่เรียกผ่าน `fetch` แบบ JSON จะล้มเหลว/พฤติกรรมไม่สอดคล้อง
- แก้แล้ว:
  - `bootstrap.php` → `verifyCsrfToken()` รองรับ `$_SERVER['HTTP_X_CSRF_TOKEN']`

### 3) Upload hardening (High)

- ปัญหา: ตรวจแค่ extension → เสี่ยงไฟล์ปลอม/อันตราย
- แก้แล้ว:
  - `core/Helpers.php::uploadFile()` เพิ่มตรวจ MIME + guard รูปภาพ/ PDF header
  - `hr/document_templates.php::dt_handleUpload()` จำกัดเป็น raster image (`png/jpg/jpeg/webp`) + ตรวจ MIME + `getimagesize()`

### 4) UX foundation / mobile shell (High)

- ปัญหา: template หลักยังไม่เทียบเท่า `tp-checkin` ในมุม PWA/mobile-safe-area และบางหน้าใส่ `<main class="content-area ...">` ซ้อนกับ wrapper จาก `templates/header.php` ทำให้ layout มี margin/padding ซ้ำ โดยเฉพาะมือถือ
- แก้แล้ว:
  - `templates/header.php` เพิ่ม mobile/PWA meta, `viewport-fit=cover`, safe-area, `100dvh`, tap highlight, input 16px, touch target ขั้นต่ำ 44px, glass-card style ใกล้ `tp-checkin`
  - `templates/footer.php` ปรับ bottom nav ให้รองรับ safe-area และย้าย toast ให้อยู่เหนือ bottom nav บนมือถือ
  - ลบ wrapper `content-area` ซ้อนใน `checkin.php`, `leave.php`, `attendance_history.php`, `hr/api_keys.php`

### 5) Toast helper compatibility (High)

- ปัญหา: `templates/footer.php::showToast()` รับ signature แบบ `(type, title, message)` แต่โค้ดส่วนใหญ่เรียกแบบ `(message, type)` ทำให้ toast แสดงหัวข้อ/ข้อความผิดและ type ไม่ถูกต้อง
- แก้แล้ว:
  - `templates/footer.php` รองรับทั้ง signature ใหม่และ legacy calls เดิมทั้งหมด

### 6) Leave API JSON cancellation (High)

- ปัญหา: `leave.php` ส่ง cancel leave เป็น JSON แต่ `api/leave.php` อ่านเฉพาะ `$_POST` ทำให้ action/token หายและยกเลิกคำขอไม่ได้
- แก้แล้ว:
  - `api/leave.php` รองรับ JSON POST แล้ว map เข้า `$_POST`
  - `leave.php` ส่ง `request_id` และ `_token` ให้ตรงกับ backend

### 7) Employee deactivate flow (High)

- ปัญหา: ปุ่ม “ลบพนักงาน” ใน `hr/employees.php` มีแค่ redirect แต่ไม่มี handler จริง และข้อความบอกว่าจะลบถาวร ทั้งที่ข้อมูล HR มี foreign key/audit dependency สูง
- แก้แล้ว:
  - เปลี่ยนเป็น “ปิดใช้งานพนักงาน” (`users.is_active = 0`) เพื่อรักษาประวัติ
  - ใช้ `POST + CSRF` แทน state-changing GET
  - เพิ่ม `Auth::log('employee_deactivate', 'users', $id)` และ flash result

### 8) Mobile card views เพิ่มเติม (Medium)

- ปัญหา: บาง employee flow ยังเป็นตารางยาวบนมือถือ แม้ระบบ `tp-checkin` ใช้ card-list เป็นหลัก
- แก้แล้ว:
  - `leave.php` เพิ่ม mobile card list สำหรับประวัติการลา
  - `attendance_history.php` เพิ่ม mobile card list สำหรับประวัติลงเวลา โดย desktop ยังใช้ table เดิม
  - `hr/settings.php` เพิ่ม mobile card list สำหรับวันหยุดและประเภทการลา และปรับกะทำงานให้เป็น card/touch target ชัดขึ้น
  - `profile.php` เพิ่ม mobile card list สำหรับข้อมูลครอบครัว และปรับผู้ติดต่อฉุกเฉิน/การศึกษา/ประวัติการทำงานให้ไม่ overflow บนจอเล็ก
  - `hr/employee_form.php` ปรับ tab navigation เป็น sticky horizontal stepper บนมือถือ และเพิ่ม sticky action bar สำหรับบันทึก/ยกเลิก
  - `hr/dayoff_approvals.php` เพิ่ม mobile card list สำหรับคำขอเปลี่ยนวันหยุด, ปรับ filters/action buttons เป็น touch target และยังคง table สำหรับ desktop

### 9) Attendance calculation service (Critical)

- ปัญหา: การคำนวณ `late_minutes`, `work_minutes`, `break_minutes`, `ot_minutes`, `early_leave_minutes`, `status` กระจายอยู่หลายไฟล์ และ `/api/v1/attendance.php` คำนวณไม่เท่าหน้า check-in หลัก
- แก้แล้ว:
  - เพิ่ม `core/Services/AttendanceService.php`
  - `api/attendance.php` ใช้ service สำหรับ check-in, check-out, HR manual adjustment
  - `/api/v1/attendance.php` ใช้ service สำหรับ external check-in/check-out แล้ว
  - `/api/v1/adjustments.php` ใช้ service ตอน approve attendance adjustment แล้ว

### 10) Payroll absence calculation no longer depends only on backfill (Critical)

- ปัญหา: `PayrollService::computeAttendanceDeductions()` นับวันขาดจาก `hr_attendances.status='ABSENT'` เป็นหลัก ถ้า cron backfill ไม่รันจะไม่หักขาดงาน
- แก้แล้ว:
  - `core/Services/PayrollService.php` เพิ่ม `findMissingAbsentDates()`
  - payroll คำนวณ missing workdays จาก schedule, holiday, pending/approved leave, approved day-off swap และ WFH โดยตรง
  - เพิ่ม breakdown kind `missing_attendance_absent` เพื่อ audit ได้ว่าวันขาดมาจากการคำนวณ expected workday ไม่ใช่ row backfill

### 11) Settings compatibility layer (Critical)

- ปัญหา: ค่า policy กระจายระหว่าง `hr_settings` และ `system_settings` ทำให้ payroll/attendance/document settings มีโอกาส drift กัน
- แก้แล้ว:
  - เพิ่ม `core/Services/SettingsService.php` เพื่อกำหนด owner ต่อ key และ fallback ระหว่างสองตาราง
  - `getSetting()`, `setSetting()`, `getSystemSetting()`, `PayrollService`, `api/attendance.php`, `hr/settings.php`, `hr/document_templates.php`, และ `CrmLineNotifierBridge.php` อ่าน/เขียนผ่าน service เดียว
  - key เวลาเริ่ม/เลิกงานและ grace sync จาก `default_work_start/default_work_end/grace_period_minutes` ไปยัง legacy `work_start_time/work_end_time/grace_period_minutes`
  - รองรับ environment ที่ยังไม่มี `system_settings` โดย fallback/skip write อย่างปลอดภัย

### 12) Upload validation for Office/GIF + upload options bug (High)

- ปัญหา: `uploadFile()` ตรวจ MIME/header แบบเข้มเฉพาะ PDF/images บางชนิด และ caller บางจุดส่ง options แบบ `['types' => ..., 'max_size' => ...]` แต่ helper เดิมอ่านเป็น list extension ตรง ๆ
- แก้แล้ว:
  - `core/Helpers.php::uploadFile()` รองรับ options `types` และ `max_size`
  - เพิ่ม MIME allowlist สำหรับ `gif`, legacy Office (`doc/xls`), Office Open XML (`docx/xlsx`)
  - เพิ่ม header guard สำหรับ GIF/image ผ่าน `getimagesize()`, legacy Office ผ่าน OLE header, และ Office Open XML ผ่าน ZIP signature + structure check เมื่อมี `ZipArchive`

### 13) Running number compatibility (High)

- ปัญหา: `api/leave.php` และ `api/certificate.php` เรียก `generateRunningNumber($pdo, type, prefix)` แต่ helper ประกาศเป็น `generateRunningNumber(prefix, table, column)` ทำให้ PHP 8 เกิด `TypeError` ตอนสร้างคำขอลา/คำขอเอกสาร
- แก้แล้ว:
  - `core/Helpers.php::generateRunningNumber()` รองรับ legacy call pattern เดิม
  - map `LEAVE` → `hr_leave_requests`, `DOC_REQUEST` → `hr_document_requests`
  - เพิ่ม validation ชื่อ table/column เพื่อกัน dynamic SQL ที่ไม่ใช่ identifier

### 14) Audit action normalization (High)

- ปัญหา: action ใน audit log ใช้หลายรูปแบบปนกัน เช่น upper-case และ lower-case ทำให้ค้นหา/report/alert ยาก
- แก้แล้ว:
  - `core/Auth.php::log()` normalize action เป็น `UPPER_SNAKE_CASE` จุดเดียว
  - เพิ่ม alias สำหรับ action สำคัญ เช่น `add_holiday` → `HOLIDAY_ADD`, `leave_request` → `LEAVE_REQUEST_CREATE`, `certificate_request` → `CERTIFICATE_REQUEST_CREATE`
  - เก็บค่าเดิมไว้ใน `new_values._raw_action` เฉพาะกรณีที่ถูกแปลง เพื่อ trace ย้อนหลังได้
  - `hr/dayoff_approvals.php` เพิ่ม audit log สำหรับ approve/reject/approve all

### 15) AttendanceService regression fixtures (Medium)

- ปัญหา: logic ลงเวลาเพิ่งถูกย้ายเป็น service กลาง แต่ยังไม่มี regression test กัน drift
- แก้แล้ว:
  - เพิ่ม `tests/attendance_service_test.php`
  - ครอบคลุม grace boundary, late minutes, planned late start, WFH, work/break/OT/early leave และ normalize short time
  - รันได้ด้วย `/Applications/XAMPP/xamppfiles/bin/php tests/attendance_service_test.php`

### 16) PayrollService missing-absence regression fixtures (Medium)

- ปัญหา: payroll now calculates missing workdays directly, but that edge logic can regress easily around holidays, leave, WFH, inactive users, and day-off swaps
- แก้แล้ว:
  - เพิ่ม `tests/payroll_service_test.php`
  - ทดสอบ `PayrollService::findMissingAbsentDates()` ผ่าน isolated SQLite fixture
  - ครอบคลุม logged dates, active holiday, pending leave, approved day-off swap, WFH user, and inactive user
  - รันได้ด้วย `/Applications/XAMPP/xamppfiles/bin/php tests/payroll_service_test.php`

### 17) SettingsService regression fixtures (Medium)

- ปัญหา: settings compatibility layer เป็นจุดร่วมของ HR policy, payroll, company document settings และ legacy aliases
- แก้แล้ว:
  - เพิ่ม `tests/settings_service_test.php`
  - ครอบคลุม HR-owned keys, system-owned keys, legacy aliases (`work_start_time`/`work_end_time`), type casting (`NUMBER`, `BOOLEAN`, `JSON`) และ `getSystemMany()`
  - `SettingsService` รองรับ schema discovery สำหรับ SQLite ใน test fixture โดยยังคง path MySQL เดิมสำหรับ production
  - รันได้ด้วย `/Applications/XAMPP/xamppfiles/bin/php tests/settings_service_test.php`

## ประเด็นที่พบ (ยังอยู่ในคิวตรวจเชิงลึก)

### Critical / High ที่ควรทำรอบถัดไป

- ยังไม่พบ Critical/High ใหม่ในรอบล่าสุด

### Data consistency (เวลา/กะ/เงินเดือน)

- เพิ่ม compatibility layer แล้ว แต่ยังควรทำ regression test สำหรับ key สำคัญ:
  - attendance policy: เวลาเริ่ม/เลิก, grace, break, work hours
  - payroll policy: social security, late/absent rates, advance leave days
  - document/company settings: company info, header/footer, e-signature flag

### UX/UI mobile-first (ต้องทำเป็นเฟส)

- ปัจจุบันมี mobile header + mobile sidebar และเริ่มมี card list บางหน้าแล้ว แต่ยังมีหลายหน้าหนักที่เป็น desktop-first
- แนวทาง: ทำ “component pattern” แบบ Checkin ต่อให้ครบ
  - card-based list แทน table บนมือถือ
  - bottom navigation สำหรับ employee flows (checkin/leave/payslip/profile)
  - touch targets ≥ 44px, spacing, input font-size 16px กัน iOS zoom
  - form ยาวควรถูกแบ่งเป็น section accordion/stepper บนมือถือ โดยเฉพาะ `hr/employee_form.php`, `profile.php`, และ settings tabs ที่ยังเหลือ form ยาว

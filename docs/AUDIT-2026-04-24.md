เอกสารนี้สรุปผลการตรวจสอบระบบ `tp-hr` แบบ “full audit” รอบแรก โดยโฟกัส **ความถูกต้องของระบบ**, **ความปลอดภัย**, และ **แนวทางยกระดับ UX/UI ให้ mobile-first** ให้ใกล้เคียงระบบ Checkin

- ขอบเขต: `tp-hr` ทั้งระบบ (web + api + external api v1) และจุดเชื่อมกับ `tp-common`/`tp-crm` ที่มีผลต่อ HR

## Quick Wins ที่แก้แล้วในโค้ด (ยังไม่ deploy)

### 1) CSRF enforcement (Critical)

- ปัญหา: บางหน้าสำคัญเรียก `verifyCsrfToken()` แต่ **ไม่ได้ตรวจผลลัพธ์** ทำให้คำสั่ง POST อาจถูกประมวลผลแม้ token ผิด/หมดอายุ
- แก้แล้ว:
  - `hr/settings.php`
  - `hr/dayoff_approvals.php`

### 2) CSRF token ผ่าน header (Correctness + UX)

- ปัญหา: frontend helper (`templates/footer.php`) ส่ง token ผ่าน `X-CSRF-Token` แต่ backend ไม่อ่าน header → บางฟังก์ชันที่เรียกผ่าน `fetch` แบบ JSON จะล้มเหลว/พฤติกรรมไม่สอดคล้อง
- แก้แล้ว:
  - `bootstrap.php` → `verifyCsrfToken()` รองรับ `$_SERVER['HTTP_X_CSRF_TOKEN']`

### 3) Upload hardening (High)

- ปัญหา: ตรวจแค่ extension → เสี่ยงไฟล์ปลอม/อันตราย
- แก้แล้ว:
  - `core/Helpers.php::uploadFile()` เพิ่มตรวจ MIME + guard รูปภาพ/ PDF header
  - `hr/document_templates.php::dt_handleUpload()` จำกัดเป็น raster image (`png/jpg/jpeg/webp`) + ตรวจ MIME + `getimagesize()`

## ประเด็นที่พบ (ยังอยู่ในคิวตรวจเชิงลึก)

### Data consistency (เวลา/กะ/เงินเดือน)

- `attendance` ใช้ `hr_settings` + `hr_work_shifts`
- `payroll` ใช้ `system_settings`
- แม้ `hr/settings.php` มี cross-sync สำหรับเวลาเริ่ม/เลิก/ผ่อนผัน แต่ยังต้อง audit ให้ครบทุก key สำคัญ (รวมถึง payroll policy)

### UX/UI mobile-first (ต้องทำเป็นเฟส)

- ปัจจุบันมี mobile header + mobile sidebar แล้ว แต่หลายหน้าหลักยังเป็น “desktop-first” (ตารางยาว/ฟอร์มยาว)
- แนวทาง: ทำ “component pattern” แบบ Checkin
  - card-based list แทน table บนมือถือ
  - bottom navigation สำหรับ employee flows (checkin/leave/payslip/profile)
  - touch targets ≥ 44px, spacing, input font-size 16px กัน iOS zoom
